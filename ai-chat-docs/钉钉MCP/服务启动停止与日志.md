# 钉钉 MCP 服务启动停止与日志

## 1. 后端服务启动与停止的实现

- **全局 PID 管理 Map**：

  - 用 `once_cell::sync::Lazy` + `Mutex<HashMap<String, u32>>` 实现全局进程 PID 管理（见 `pid_manager.rs`）。
  - 每个被管理的服务用唯一 key（如 `dingding_mcp`）存储其 PID，支持后续扩展多服务。
  - 所有进程操作（启动、检测、停止）均通过 PID 进行，无需全局 Child 句柄。

- **启动流程**：

  - 启动服务时，`run_command_background_stream` 启动进程并返回 PID，自动存入 PID 管理器。
  - 若已存在且存活的 PID，直接复用，不重复启动。

- **停止流程**：

  - 通过 PID 管理器查找并 kill 指定 key 的进程（macOS 用 `nix`，Windows 用 `OpenProcess/TerminateProcess`）。
  - 停止后自动移除 PID 记录。

- **检测流程**：

  - 通过 PID 判断进程是否存活（macOS 用 `kill(pid, 0)`，Windows 用 `OpenProcess`）。

- **跨平台兼容**：

  - 进程操作内部已做 macOS/Windows 区分，接口统一。

- **代码示例**：

  ```rust
  // 设置PID
  PidManager::set_pid("dingding_mcp", pid);
  // 检查是否存活
  let running = PidManager::get_pid("dingding_mcp").map_or(false, |pid| is_alive(pid));
  // 停止服务
  PidManager::kill_pid("dingding_mcp");
  ```

- **依赖**：
  - macOS: 需 `nix` crate
  - Windows: 需 `windows-sys` crate

## 2. 命令执行与日志推送

- 封装了两类命令执行工具：
  - `run_command_stream`：同步执行命令，等待命令结束，实时推送 stdout/stderr 到前端。
  - `run_command_background_stream`：异步后台执行服务，实时推送日志，返回进程 PID 并存入全局管理。
- 日志推送机制：
  - 后端通过 tauri 的 emit 事件机制，将命令输出（stdout/stderr）实时推送到前端。
  - 事件名统一为 `cmd_output` 和 `cmd_output_err`，便于前端统一监听。

## 3. 服务状态检测

- `is_start` 方法：
  - 判断 MCP 服务进程 PID 是否存在且存活。
  - 便于前端/业务层随时获知服务运行状态。

## 4. 启动/停止/检测逻辑的调用关系

- `start` 方法为私有，仅负责进程管理和启动。
- `check_and_start` 作为对外入口，先检测 MCP 是否已安装，再调用 start。
- `stop` 方法只做进程 kill。
- `detect` 方法用于判断 MCP 是否已安装（通过 which/where 检查二进制是否存在）。

## 5. 前端日志展示集成

- Layout 组件全局 useEffect 监听 `cmd_output`/`cmd_output_err` 事件，将日志存入 context，任何弹窗或页面都可随时查看历史输出。
- 日志展示与弹窗解耦，支持全局实时查看。
- 支持命令行输出高亮、滚动、分 stderr/stdout。

## 6. 依赖与注意事项

- 需在 `Cargo.toml` 添加 `once_cell = "1"`、`nix`（macOS）、`windows-sys`（Windows）等依赖。
- 进程管理相关代码需注意线程安全（Mutex）和跨平台兼容。
- 若需扩展更多服务管理能力（如重启、健康检查、端口检测等），可在此基础上继续封装。

本方案实现了钉钉 MCP 服务的全生命周期管理与日志流前后端集成，适合所有需要"服务型命令+日志流"场景的 Rust+Tauri 应用。

## 知识总结

- **Rust 子进程管理**：用于启动和控制外部程序（如服务进程），常用 `std::process::Command`，后台运行用 `.spawn()`，同步等待用 `.output()`。遇到子进程无法杀死时可用 `kill()`。

- **全局单例与线程安全**：全局状态（如进程句柄）用 `once_cell::sync::Lazy` + `Mutex` 实现线程安全单例。常见报错"unresolved crate once_cell"需在 `Cargo.toml` 添加依赖。

- **跨平台命令兼容**：不同操作系统命令名/参数不同，Rust 用 `#[cfg(target_os = "xxx")]` 区分。路径分隔符、可执行文件后缀等也需兼容。

- **命令输出实时读取**：用 `BufReader` + 多线程读取 stdout/stderr，避免阻塞。日志可通过事件推送到前端。

- **Tauri 事件推送**：后端用 `AppHandle.emit` 向前端推送消息，前端用事件监听获取日志。常见问题是 emit 需引入 trait：`use tauri::Emitter;`。

- **前端全局日志流**：用 React Context 存储日志，useEffect 注册事件监听，保证日志全局可见。

- **依赖管理**：Rust 三方库需在 `Cargo.toml` 添加，缺失依赖会导致"unresolved crate"报错。

- **进程生命周期管理**：用 `try_wait` 检查进程是否存活，已退出则清理，防止僵尸进程。

- **常见报错与解决**：

  - `no method named 'emit'`：需 `use tauri::Emitter;`
  - `unresolved crate once_cell`：需 `cargo add once_cell`
  - 进程未退出导致重复启动：需全局管理进程句柄并检测存活

- **代码结构分层**：工具函数、服务管理、前端集成分离，便于维护和扩展。
